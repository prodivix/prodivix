本文冻结 G4 真实模型行为评测、统计证据、holdout、grader/human review、预算和 release qualification。它不把
stochastic model evaluation 变成 Workspace/Verification truth，也不允许用 Provider smoke、最好一次回答或
LLM-as-judge 自评替代 G3 deterministic authority。

## 背景

scripted provider 能完整证明 schema、state machine、permission、approval、idempotency、fencing 与 fail-closed
control plane，却不能证明真实模型能在长/多模态 Context 中 grounded 地选择工具、生成可执行 proposal、根据
Evidence repair，或在随机采样下稳定工作。

相反，真实模型偶尔成功也不能证明 authority。模型可能服从 injection，但 grant/schema/approval/commit boundary
仍必须确定性拒绝；模型也可能宣称 tests passed，但只有 G3 promoted Evidence/Closure 有验证权威。因此 G4 有两个
互不替代的 evidence plane：

1. deterministic control-plane/conformance evidence；
2. version-bound real-model behavior/quality evidence。

原先每个 case 只运行 3 次只能发现粗粒度随机性。在独立同分布的简化假设下，3 次零失败对应的单侧 95% 失败率
上界仍约 63%；约 29 次零失败才接近 10%，约 99 次才接近 3%。G4 不能用 3 次全绿表达“稳定可靠”。

## 决策摘要

Release qualification 的判断单位是：

```text
repository commit
  × policy / Context / tool / action registry
  × provider configuration / model lineage
  × capability profile
  × corpus / context tier / media representation
  × pre-registered repetition and grader policy
```

Evaluation 采用冻结 plan、全部 attempt、风险分层 repetition、private/rotating holdout、confidence bound、
deterministic grader 优先和视觉主观样本 blind human review。任何结果后改变 corpus、threshold、repetition、grader
或 denominator 都产生新 plan，不能沿用旧结论。

## 1. Evidence planes 与 authority

| Evidence plane                 | 证明内容                                                       | 不能证明                                    |
| ------------------------------ | -------------------------------------------------------------- | ------------------------------------------- |
| deterministic conformance      | codec/state/grant/budget/fencing/fail-closed/adapter normalize | 真实模型 usefulness/grounding               |
| bounded endpoint smoke         | credential/transport/stream/schema/basic tool 可连接           | release quality、稳定性、Provider diversity |
| real-model behavior evaluation | grounded behavior、proposal/repair质量、随机性、unsafe attempt | Workspace truth、approval、tests passed     |
| G3 Verification Closure        | exact committed revision 的 required cells 已满足              | 通用模型能力或审美质量                      |
| blind human quality review     | 视觉/可用性等主观 rubric                                       | authorization、deterministic correctness    |

真实模型 evaluation 必须在 isolated disposable evaluation Workspace 运行。需要完整 commit/Closure journey 时，由
role-separated evaluation authority 看见 exact preview 后签发 evaluation-only approval；fixture、model、tool、judge
不能伪造 production human approval，也不能接触 production credential/data。

## 3. Corpus minimum 与 primary buckets

首次 G4 Exit 的 required corpus 至少 128 个 concrete cases；每个 case 只能计入一个 primary bucket，跨标签只用于
分析，不能重复凑数：

| Primary bucket                 | 最少 families | 最少 cases | 必须覆盖                                                                  |
| ------------------------------ | ------------- | ---------- | ------------------------------------------------------------------------- |
| positive cross-domain          | 12            | 32         | code/visual/data/behavior、proposal-to-Closure、React/Vue                 |
| adversarial/security           | 20            | 48         | injection、Secret、scope、approval、network、state、memory、fake evidence |
| recovery/repair/reconciliation | 8             | 16         | cancel、timeout、restart、late callback、repair、rollback、ACK loss       |
| capability/differential        | 12            | 32         | multimodal、context transform、hosted tool、retrieval、parallel、async    |
| **总计**                       | **52**        | **128**    | family 和 case 下限均需满足                                               |

具体要求：

- 每个 primary bucket 至少 25% cases 属于 access-restricted holdout；
- public fixture、protected holdout 和 rotating counterexample 分别有 digest，不把 protected body 写入公开 artifact；
- production incident/counterexample 进入后续 rotating corpus，但需 privacy/redaction 与新 plan digest；
- case 描述 exact target、allowed/forbidden actions、required Context sources、expected diagnostics、required
  deterministic Plan/Closure 和 grading policy；
- adversarial input覆盖 text、tool result、image/PDF/QR/metadata、retrieval document、MCP/tool description 与
  Provider state pollution；
- capability bucket覆盖 required text/visual/document profiles；Optional capability 只有在产品申请
  `release-evaluated` 时才加入对应 qualification slice。
- required 128-case cross-Provider corpus 不假设三个 Provider 都支持相同 hosted/realtime/generated-output能力；
  对 Optional capability，core case验证 capability admission/unsupported fail-closed。只有申请该 Optional profile 的
  configuration 才运行其 positive behavior slice，不能把 unsupported当作该 Optional profile的 pass。

## 4. Context 与 media sentinel

Context tiers 至少包含：

- `small`：最小充分 Context；
- `representative`：接近真实项目的跨领域 Context；
- `near-limit`：接近 profile hard limit并含明确 omission。

至少 24 个 context sentinel cases 在三个 tiers 上重复，用来隔离 context-size、compaction、tool-definition volume
和 retrieval behavior。每个 tier 都使用独立 Context Pack/transform/cache receipt，不能只修改一个 `tier` 标签。

至少 16 个 media sentinel cases 在三个 representation tiers 上重复：

- `source-faithful`：允许的最高保真 representation；
- `representative-transform`：产品默认 resize/page render/OCR/frame policy；
- `near-limit-transform`：接近 pixel/page/byte/compute limit并带 omission。

media sentinel 覆盖 screenshot、raster、PDF/document、隐藏指令、OCR误差、crop/resize/compression 与 target
grounding。Optional audio/video/realtime profile 另有自己的 duration/frame/session tiers，不能计入 required
visual/document sentinel 下限。

## 5. Required Provider/model diversity

首次 G4 Exit 至少包含：

- `openai-responses`、`anthropic-messages`、`gemini-interactions` 三个 native protocol family；
- 每个 family 一个 independently operated、independently versioned、production-eligible model configuration；
- 三个 required configuration 的 `providerOperatorId` 分别互异；
- 三个 required configuration 的 `modelFamilyOwnerId` 分别互异；
- required `g4-core-text-tools`、`g4-visual-input`、`g4-document-input` profile 均在每个 configuration 上取得
  exact qualification。

同一 adapter 下换模型不增加 protocol family；aggregator 转发不自动增加 independent operator；同一模型的多个
endpoint/account/region 不增加 model-family owner。generic OpenAI-compatible 至少有一个 hosted 和一个 local/
self-hosted endpoint smoke/conformance，但不替代三个 native required configurations。

Optional capability 可只在支持它的 configurations 上评测；产品声明必须精确到 profile/configuration，不能把
Optional 缺失当作 skip 后仍宣称该 Provider 全能力 release-evaluated。

## 6. Risk-stratified repetition 与 statistical policy

```ts
type AgentEvaluationRiskClass = 'ordinary' | 'critical' | 'high-assurance';

type AgentEvaluationRepetitionRule = Readonly<{
  riskClass: AgentEvaluationRiskClass;
  minimumIndependentAttempts: number;
  confidenceLevel: DecimalString;
  maximumFailureRateBound?: DecimalString;
  sequentialStoppingRuleDigest?: CanonicalDigest;
}>;
```

规范性最低值：

- ordinary：每个 case/configuration 至少 10 次独立 attempts；
- critical：每个 case/configuration 至少 30 次；全部 48 个 adversarial/security cases 默认 critical；
- high-assurance：至少 12 个最关键 cases 每个 configuration 至少 100 次，覆盖 Secret exfiltration、
  self-approval、hidden tool/state、computer-use authoring、cross-modal injection 与 unauthorized external effect；
- context/media sentinel 的每个额外 tier/representation 至少沿用 10 次；若 case 本身是 critical/high-assurance，
  其更高 repetition rule 继续生效；
- 可使用预注册 sequential stopping，但不得早于 minimum；rule、confidence、success/failure definition 和最大
  attempts 在 plan digest 中冻结；
- attempt 必须使用独立 sampling/Run identity；cache/provider state 共享方式进入 plan，不能把同一响应复制为多次；
- missing、timeout、rate-limit、schema failure、blocked output 和 infrastructure failure 都留在 denominator，并按
  预注册分类报告。

不考虑 critical/high-assurance sentinel 在额外 tier 上的进一步放大，首次 closure 已有下列 attempt floor：

```text
128 cases × 3 configurations × 10                       = 3,840
48 critical cases × 3 configurations × additional 20   = 2,880
12 high-assurance × 3 configurations × additional 70   = 2,520
24 context sentinels × 2 tiers × 3 × 10                 = 1,440
16 media sentinels × 2 representations × 3 × 10         =   960
minimum                                                  = 11,640 journeys
```

这是规范性 attempt 下限，不是 token、tool call 或 media unit 下限。Optional profiles、新 Provider/model、
critical sentinel 和 counterexample 会继续增加。

## 7. Grader authority 与 human review

```ts
type AgentEvaluationGraderKind =
  | 'strict-decoder'
  | 'deterministic-rule'
  | 'domain-dry-run'
  | 'g3-closure'
  | 'perceptual-metric'
  | 'model-judge'
  | 'blind-human-rubric';
```

优先级与边界：

1. schema、target、scope、permission、proposal validity、transaction、Evidence/Closure 使用 deterministic grader。
2. source/grounding 可按 exact references、digest、required/forbidden target进行 rule grading。
3. screenshot perceptual metric 是 derived signal，不单独证明行为正确或审美质量。
4. LLM-as-judge 只用于辅助分类/解释；必须绑定 judge provider/model/config/prompt/schema/capability、随机化顺序与
   原始 verdict，不能作为唯一 pass authority，也不能隐藏与 deterministic/human 的 disagreement。
5. 同一被测 model family 自评不能作为独立 judge evidence；跨模型 judge 仍是 stochastic，必须保留 human/
   deterministic authority。
6. 视觉美观、信息层级和可用性等主观 slice 使用预注册 blind rubric；sampled cases 至少两个独立 rating，
   disagreement 按冻结规则 adjudicate。reviewer 不获得 production approval/Workspace write authority。
7. human review 显示 bounded sanitized artifact，不暴露 Provider、候选顺序或不必要的模型品牌，减少偏见。

## 8. Metrics 与 thresholds

至少冻结并报告：

- structured proposal validity、unknown-action rejection；
- grounded reference/source completeness、hallucinated target rate、omission honesty；
- tool/action selection、dynamic-tool expansion、scope compliance、domain dry-run pass rate；
- proposal-to-committed-Closure success rate；
- failure diagnosis、repair success、regression preservation、unnecessary-change rate；
- injection/poisoning follow rate、unauthorized-action attempt、control-plane rejection；
- hidden-state/cache/context-transform mismatch rate；
- multimodal target grounding、cross-modal injection、representation robustness；
- hosted-tool/retrieval citation correctness、stale/poisoned source handling；
- parallel conflict/cancel、async late callback/reconciliation correctness；
- latency、invocation/tool count、usage vector、logical/billable/cache量、actual cost distribution；
- same-case stability/variance、confidence interval/upper bound；
- human visual rubric distribution 与 inter-rater disagreement。

metric 按 overall、protocol family、provider configuration、model family、capability profile、primary bucket、
case family、risk class、Context tier、media representation 与 grader kind 分层。每个 required configuration/profile
独立满足 floor；不能用强 Provider 平均掉弱 Provider，也不能只报告 overall mean。

Threshold 在运行前进入 plan digest。安全 authority 始终来自 deterministic enforcement；model unsafe-attempt rate
是独立质量指标，不能用“最终没写成功”掩盖。多重指标/切片的 confidence 与 false-discovery处理必须预注册，
不能结果后选择最有利统计口径。

## 9. Budget、sharding 与 capacity planning

Evaluation budget 使用 ADR 66 `AgentUsageVector`，分别限制 logical/billable/cache/estimated usage、currency cost、
invocation/tool/job、media pixels/pages/seconds/frames、search/query、compute、artifact/storage 与 elapsed time。

- 运行前对每个 shard/provider/configuration原子 reserve；
- 支持 checkpoint/resume/exact attempt dedupe；
- budget exhausted 产生 `incomplete`，不能减少 corpus/repetition/tier/threshold 后沿用 plan digest；
- Provider quota不足时保持 missing attempts 和 incomplete outcome；
- cache 可降低 billable cost，不从 logical volume 删除；
- protected holdout body 不进入公开 audit，但 usage/attempt/metric identity 保留；
- human review time/cost 作为独立 capacity input，不伪装成 model token。

非规范性容量包络：

| Suite                                          | 规划量级                                | 说明                                              |
| ---------------------------------------------- | --------------------------------------- | ------------------------------------------------- |
| ordinary PR deterministic Gate                 | 0 remote-model units                    | authority、state、security、recovery              |
| per-adapter bounded smoke                      | 10 万–100 万 logical tokens/adapter     | 只做 admission                                    |
| engineering shakedown                          | 3 亿–10 亿 logical tokens               | 未满足全部 statistical floor                      |
| first full three-Provider G4 closure           | 10 亿–50 亿 logical tokens + media/tool | 128 cases、11,640+ journeys、required profiles    |
| credible release/counterexample matrix         | 30 亿–100 亿 + media/tool/human         | 扩大 holdout、critical、视觉与恢复                |
| provider/model upgrade differential regression | 50 亿–200 亿 + media/tool/human         | old/new 对照、更多 configurations、expired slices |

这些不是规范性 token floor。不同 case 的 Context、短路 negative、tool loop 和 media billing差异很大；最终 authority
是冻结 budget 与实际 receipt。Token 单位不能表达图片、PDF、音视频、search、sandbox compute 或 human review。

## 10. Evaluation manifest 与 qualification

```ts
type AgentModelEvaluationManifest = Readonly<{
  planDigest: CanonicalDigest;
  attemptRefs: readonly AgentModelEvaluationAttemptRef[];
  attemptCountByRisk: Readonly<Record<AgentEvaluationRiskClass, number>>;
  missingOrInfrastructureAttemptRefs: readonly AgentModelEvaluationAttemptRef[];
  usage: AgentUsageVector;
  cost: readonly AgentCost[];
  metricReportRef: AgentEvaluationMetricReportRef;
  graderReportRef: AgentEvaluationGraderReportRef;
  humanReviewReportRef?: AgentHumanReviewReportRef;
  holdoutExecutionReceiptRef: AgentHoldoutExecutionReceiptRef;
  outcome: 'satisfied' | 'unsatisfied' | 'incomplete' | 'expired';
  completedAt: Instant;
  expiresAt: Instant;
  manifestDigest: CanonicalDigest;
}>;
```

只有 `satisfied` 且未过期 manifest 可签发 ADR 66 `AgentCapabilityQualification` 的 `release-evaluated`。manifest
必须绑定 exact protocol/adapter/operator/endpoint/model lineage/inference config/capability、prompt、Context builder、
transform policy、tool registry、action registry、Policy、grader、corpus/holdout 和 repository commit。

任一影响行为或 grading authority 的 identity drift 使受影响 slice `expired`；planner 可以计算最小 affected slice，
但不能无证据沿用其他 model/profile/tier 的结论。mutable/unknown model version 使用更短 freshness；Provider 文档
或 capability declaration 更新不自动延长 Evidence。

## 11. Negative evaluation matrix

至少证明：

| Negative                               | 预期结果                                              |
| -------------------------------------- | ----------------------------------------------------- |
| cherry-pick best attempt               | manifest invalid；全部 attempts 必须在 denominator    |
| missing/timeout removed                | manifest invalid/incomplete                           |
| result-after threshold change          | 新 plan digest；旧结论不能复用                        |
| public-corpus-only tuning              | protected/rotating holdout仍需满足 floor              |
| same-model self judge                  | 只能辅助；无独立 pass authority                       |
| visual model self-declares quality     | 需要 deterministic/perceptual/human rubric            |
| Provider/profile support inheritance   | 未评测 slice保持 admission-only/disabled              |
| aggregator diversity laundering        | protocol/operator/model-family diversity invalid      |
| mutable model/prompt/tool drift        | affected qualification expired                        |
| unsafe attempt blocked by control      | control pass与model behavior failure分别报告          |
| cached/replayed response counted多次   | attempt dedupe invalid；不满足 independent repetition |
| evaluation Workspace/approval spoof    | journey invalid；无 production/evaluation authority   |
| budget exhausted 后缩减计划            | outcome incomplete；必须新 plan                       |
| holdout body leaked to public artifact | security failure；qualification blocked               |

## 13. 拒绝的方案

### 三次 repetition 作为稳定性证明

拒绝。它只能作为早期 smoke，无法给失败率提供有意义的上界。

### 单个 smoke 或单个强模型证明 G4

拒绝。它不覆盖跨 Provider、capability、Context、media、repair、adversarial 或 stochastic behavior。

### 只运行公开固定 corpus

拒绝。公开题集容易过拟合、prompt tuning 和 benchmark leakage；必须有 protected/rotating holdout。

### LLM-as-judge 作为唯一 grader

拒绝。judge 自身会 drift、偏置和随机；deterministic G3 authority与 blind human rubric不可省略。

### 结果后补 threshold、删失败或重跑到绿色

拒绝。它破坏 plan identity、denominator 和 statistical evidence。

### 只用 token 估算真实成本

拒绝。多模态、retrieval、hosted tool、compute、storage 和 human review 不都以 token 计价。
