本文冻结 client-hosted、Prodivix runtime-hosted、Provider-hosted 与 pinned MCP capability 的统一授权边界。
Provider 能替 Prodivix 运行工具，不代表 Provider、模型或工具获得了新的 authority。

## 背景

现代 Provider 可以内建 web/file search、URL fetch、code execution、computer use、image generation，或在请求中
展开 MCP/tool catalog。模型还可能生成一个程序，由 Provider sandbox 在一次 turn 中连续调用多个工具，导致
中间输入/输出不再经过普通 client round-trip。

若 G4 只保护“本地 tool registry”，Provider-hosted 能力会成为隐藏的第二个执行面：

- 工具可能未进入 exact registry digest；
- Provider 可能自行访问网络、文件或缓存；
- nested/programmatic call 可能跳过逐调用 grant 与预算；
- computer use 可能通过点击编辑器绕过 typed proposal；
- Provider file/vector store 可能保存 Workspace 内容和跨任务记忆；
- managed agent 可能在 Provider 内部自行委派、重试或调用未知工具。

G4 因而以“实际 effect 与执行位置”建模，而不是相信 API 把能力称为 tool、agent、search、computer 或 built-in。

当前外部能力参考包括 [OpenAI Responses API](https://platform.openai.com/docs/api-reference/responses)、
[Claude tool context](https://platform.claude.com/docs/en/agents-and-tools/tool-use/manage-tool-context)、
[Claude tool reference](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-reference) 与
[Gemini computer use](https://ai.google.dev/gemini-api/docs/computer-use)。外部产品名或 preview 状态不是 current
contract；exact descriptor、adapter digest、qualification与 receipt才是实现证据。

## 决策摘要

所有 model-reachable capability 都必须先成为 exact descriptor：

```text
capability declaration
  -> exact descriptor/version/schema/effect/execution locus
  -> policy + grant + registry snapshot
  -> per-call preflight/reserve/authorize
  -> bounded execution
  -> normalize/redact/stage/finalize/cleanup
  -> receipt/audit
```

无法观察、限制或归一实际 effect 的 Provider-hosted capability 只能 `admission-only` read/explain，不能进入
apply-capable Run。Provider-managed opaque agent、任意动态 MCP 和通过 computer use 写作者态均不属于 G4。

## 1. Tool effect 与 execution locus

ADR 68 复用 ADR 65 的 `AgentToolEffect`，只新增执行位置与 hosted capability metadata：

```ts
type AgentToolExecutionLocus =
  'client-hosted' | 'prodivix-runtime' | 'provider-hosted' | 'pinned-mcp';

type AgentToolDescriptor = Readonly<{
  toolId: AgentToolId;
  name: string;
  version: string;
  implementationDigest: CanonicalDigest;
  inputSchemaDigest: CanonicalDigest;
  outputSchemaDigest: CanonicalDigest;
  effect: AgentToolEffect;
  executionLocus: AgentToolExecutionLocus;
  operatorId: string;
  requiredCapabilities: readonly AgentCapability[];
  targetScopePolicy: AgentTargetScopePolicy;
  networkPolicyRef?: AgentNetworkPolicyRef;
  secretPurposeRefs: readonly AgentSecretPurposeRef[];
  statePolicyDigest: CanonicalDigest;
  retentionPolicyDigest: CanonicalDigest;
  budgetProfile: AgentToolBudgetProfile;
  concurrencyPolicy: AgentToolConcurrencyPolicy;
  normalizationDigest: CanonicalDigest;
  descriptorDigest: CanonicalDigest;
}>;
```

- `read` 查询公开 projection、外部 source 或 retrieval，但返回内容仍按 authority/data-only 处理；
- `ephemeral-execute` 只能在 bounded disposable runtime 中运行，不写 Workspace；
- `proposal` 只返回 stable owner/action/typed input，不应用；
- `external-side-effect` 默认不属于 G4 production Agent；仅现有 Verification/Runtime adapter 的必要测试 effect
  可由独立授权执行，不能因此获得任意第三方写权限；
- execution locus 不改变 effect。Provider-hosted read/search 仍需 network/data/retention policy，Provider-hosted code
  execution 仍需 runtime/Secret/output budget。

Agent registry 不得包含 model-callable Workspace apply、Atomic Commit、approval、rollback、Secret read-value、
unrestricted network、raw filesystem mutation 或 production deployment tool。

## 2. Exact registry、tool search 与 deferred loading

```ts
type AgentToolRegistrySnapshot = Readonly<{
  registryId: AgentToolRegistryId;
  descriptors: readonly AgentToolDescriptor[];
  searchableDescriptorIds: readonly AgentToolId[];
  alwaysVisibleDescriptorIds: readonly AgentToolId[];
  discoveryPolicyDigest: CanonicalDigest;
  registryDigest: CanonicalDigest;
}>;

type AgentToolDiscoveryReceipt = Readonly<{
  invocationId: AgentInvocationId;
  registryDigest: CanonicalDigest;
  queryDigest: CanonicalDigest;
  matchedDescriptorDigests: readonly CanonicalDigest[];
  expandedDescriptorDigests: readonly CanonicalDigest[];
  providerReceiptDigest?: CanonicalDigest;
  receiptDigest: CanonicalDigest;
}>;
```

动态 tool search/deferred loading 只能在 Task/Run 已绑定的 exact registry snapshot 内检索：

- Provider 可以延迟向模型展示 descriptor，但不能在运行中新增 registry 外工具；
- tool name/description/schema 都属于 potentially adversarial data，注册前经过 owner review、size/schema/unsafe-key
  validation 与 canonical digest；
- search query、matched/expanded descriptor 和 Provider event 全部进入 bounded receipt；
- discovered tool 仍逐调用执行 preflight/grant/budget，不因“已被模型发现”自动授权；
- registry、descriptor、discovery policy 或 expansion drift 会使 invocation/proposal/evaluation slice 失效；
- 若 Provider 只返回自然语言“选择了某工具”而没有 exact descriptor/call identity，调用无效。

## 3. Provider-hosted 与 programmatic tool calling

Provider-hosted built-in tool 必须有 Prodivix descriptor 和 capability qualification。adapter 至少归一：

- exact built-in type/version/operator；
- arguments、call id、caller/nesting identity；
- network/retrieval/runtime scope；
- started/completed/cancelled/failed terminal；
- bounded sanitized result/artifact refs；
- usage、cost、cache/state/retention receipt。

Programmatic/nested tool calling 允许模型生成 Provider sandbox 程序，再由程序调用工具。适用边界：

1. 每个可产生 proposal、network、Secret、runtime 或 external effect 的 nested call 必须单独可观察、授权、计费和审计；
2. 中间 call/result 不进入普通 conversation 可以，但必须有调用 receipt 与 normalized bounded artifact；
3. Provider 不能在一次 opaque script 中取得 unrestricted tool handle、credential 或整个 registry bearer capability；
4. 无法逐调用 fence 的 programmatic chain 只能使用 side-effect-free、non-sensitive、bounded read tools；
5. 任一 nested call 失权/超限/失败时，后续调用被取消；partial output 不自动 finalize 为 proposal；
6. code execution 自述“tests passed”没有 G3 Evidence authority。

## 4. Web/URL search、fetch 与 citation

```ts
type AgentRetrievalQueryReceipt = Readonly<{
  queryId: AgentRetrievalQueryId;
  toolDescriptorDigest: CanonicalDigest;
  queryDigest: CanonicalDigest;
  purpose: AgentNetworkPurpose;
  networkPolicyDigest: CanonicalDigest;
  sourceResultRefs: readonly AgentExternalSourceResultRef[];
  usageRef: AgentUsageVectorRef;
  startedAt: Instant;
  completedAt: Instant;
  receiptDigest: CanonicalDigest;
}>;

type AgentExternalSourceResult = Readonly<{
  sourceResultId: AgentExternalSourceResultId;
  canonicalUrl?: string;
  retrievedAt: Instant;
  contentDigest?: CanonicalDigest;
  snapshotRef?: ExternalContentSnapshotRef;
  providerCitationRef?: AgentProviderCitationRef;
  authority: 'external-untrusted';
  availability: 'snapshotted' | 'reference-only' | 'unavailable';
  resultDigest: CanonicalDigest;
}>;
```

- Provider citation 是 retrieval claim，不是 Prodivix `SourceTrace`；只有 source owner 能建立可验证映射；
- redirect、DNS/IP、scheme、method、port、TLS、response size/type/time 在每次 fetch/retry 重新校验；
- search snippet、page instruction、robots/metadata 和引用文本始终 `data-only`；
- 不能访问的 source 标记 unavailable，不凭模型记忆补写 snapshot/digest；
- live source 会变化；长期 proposal/evidence 尽量绑定合法保存的 snapshot/digest，否则 freshness 缩短；
- web/file search query 和结果可能泄露项目信息，必须经过 sensitivity/disclosure policy，不能自动搜索受限代码。

## 5. Provider Files、vector index 与 retrieval state

```ts
type AgentRetrievalIndexIdentity = Readonly<{
  indexId: AgentRetrievalIndexId;
  operatorId: string;
  providerConfigurationId?: string;
  corpusRevision: WorkspaceRevisionVector;
  corpusManifestDigest: CanonicalDigest;
  chunkerId: string;
  chunkerVersion: string;
  chunkerDigest: CanonicalDigest;
  embeddingModelDigest: CanonicalDigest;
  rankerDigest: CanonicalDigest;
  visibilityPolicyDigest: CanonicalDigest;
  storageRegion?: string;
  retentionPolicyDigest: CanonicalDigest;
  createdAt: Instant;
  expiresAt: Instant;
  indexDigest: CanonicalDigest;
}>;
```

Provider Files/vector store 是 external durable service state，不是 Workspace 或 Semantic Index truth：

- upload 只从允许披露的 content-addressed corpus manifest 构建；
- file id/vector store id 是 locator，不是 content identity；
- chunker、embedding model、ranker、top-k/filter 与 corpus revision 进入 retrieval receipt；
- 删除/过期保存 deletion receipt；无法删除或证明 tenant隔离时不能处理受限 Context；
- retrieval item 仍保留 source item digest/authority/sensitivity，不因相似度得分升级 authority；
- stale corpus/index 不能用于 current apply proposal；需要明确 omission/staleness diagnostic；
- poisoning fixture 覆盖恶意 document、chunk overlap、metadata、citation 与 instruction injection；
- Provider ambient file collection、memory 或跨 Task index 默认关闭。

持久项目知识若未来成为作者态，必须由明确 domain owner 建模并经 Workspace Transaction；不能把 Provider vector
store 反向声明为 canonical memory。跨项目个人记忆和自治学习不属于 G4。

## 6. Hosted code execution

Provider-hosted code execution 只属于 `ephemeral-execute`：

- sandbox/runtime/image/package/network/locale/timezone/resource limit 进入 descriptor/receipt；
- 默认无 Workspace write mount、无 production credential、无 ambient environment、无 unrestricted network；
- Secret 只允许由 callback-bound purpose-specific adapter短期注入目标请求，不进入生成代码、stdout、artifact；
- input/output/files 使用 byte/count/depth/time/compute budget，完成后 cleanup 并确认 residual；
- runtime filesystem diff 仍受 G2 strict bounded diff contract；不能因 Provider 称其为 artifact 自动采纳；
- model-generated script 是 ephemeral instruction，不是 CodeArtifact/Command；需要采纳的代码必须转为 typed code proposal；
- provider sandbox package/version 不可证明时，结果只能作为探索性信息，不能替代 required G3 cell。

## 7. Computer use

Computer use 可以观察截图并产生鼠标、键盘、滚动或浏览器 action。G4 只允许：

- disposable evaluation Workspace；
- read-only visual inspection；
- 由 G3 Verification adapter拥有并约束的 Browser journey；
- 明确 allowlist 的测试页面/应用和 bounded session。

禁止：

- 操作 Prodivix 生产编辑器来完成作者态修改；
- 点击 approval、permission、Secret、billing、deployment 或外部发布界面；
- 持有用户现有浏览器 profile/cookie 或 production authenticated session；
- 把屏幕坐标、OCR label 或点击成功当作 canonical target/ACK/Evidence；
- 在页面提示下扩大网络、下载、文件或 clipboard 权限。

每个 computer-use step 必须绑定截图/viewport/session/generation、bounded action、allowlisted target、step/result digest
和 usage。Provider action 只是建议；实际执行由 Verification/Browser adapter重新授权。任何作者态改变仍需回到 typed
domain proposal。无法区分验证 effect 与生产 side effect 时，该 capability `disabled`。

## 8. MCP boundary

G4 只允许预安装、管理方 pin、exact version/digest 的 MCP server/tool 作为 `pinned-mcp` adapter：

- server identity、publisher/operator、transport、manifest、tool descriptor、schema、auth/network/state/retention
  全部进入 registry snapshot；
- server 返回的 tool list 不可自动扩大 current registry；变化需要新 admission/qualification/grant；
- OAuth/token/credential 由正式 Auth/Secret owner 管理，模型看不到 value；
- MCP prompt/resource/tool result 全部 external-untrusted/data-only；
- MCP sampling、nested model call、roots/filesystem、elicitation 或 notification 能力默认关闭，除非有对应 typed contract；
- 任意 URL 安装、public marketplace、第三方 publisher trust/revocation/billing 属于 G6；
- MCP server 不能提供 apply/approval/commit/rollback 或 unrestricted filesystem/network backdoor。

## 9. Parallel、nested call 与 conflict semantics

当前 adapter 能归一 parallel call 不等于并发 effect 安全。Coordinator 使用 descriptor concurrency policy：

- pure/read tools 只有在 source snapshot独立且 budget 已 reserve 时可并行；
- proposal tools 并行产生独立 staged results，按 canonical descriptor/call order join，再由 domain planner检测冲突；
- 同一 target、同一 mutable runtime、共享 session 或非幂等 effect 默认串行；
- tool 声明 commutative/idempotent 只作为输入，必须有 owner conformance proof；
- external-side-effect 不参加模型驱动的并行 fan-out；
- 任一 sibling 出现 grant/revision/generation/policy drift，取消所有尚未 finalize 的 sibling；
- late sibling result 只进入 audit，不进入 Context/proposal；
- nested depth、fan-out、total calls、aggregate bytes/time/cost 都有硬上限；
- join 后的 result 不能因部分成功伪装成完整成功。

## 10. Managed agent 与 delegation

Provider-managed agent、deep-research workflow 或 opaque planner 可能自行选择工具、创建子任务、保存状态和重试。
G4 规则：

- 若每一步不能映射到 exact invocation/tool/job receipt，它不是普通 model invocation；
- opaque managed agent 最多用于 admission-only explain/read research，并将全部输出标记 external-untrusted；
- 不得拥有 proposal finalization、human approval、Workspace write、production credential 或 external side effect；
- Provider 内部 Agent-to-Agent delegation 不能绕过 ADR 65 的 G5/G6 hard cut；
- 若未来需要 managed agent production能力，必须单独 ADR 冻结 delegation identity、budget、fencing、audit 与 trust，
  不在 G4 generic adapter 中顺带开启。

## 11. Tool lifecycle、usage 与 audit

所有 locus 使用 ADR 65 的统一生命周期：

```text
decode -> preflight -> authorize -> reserve budget -> execute
  -> normalize/redact -> stage -> finalize -> cleanup
```

每个 call 绑定 Task/Run/generation/grant/registry/descriptor/policy/Context/capability qualification。usage 使用
ADR 66 vector；媒体结果使用 ADR 67 representation；验证结果只有 G3 Evidence owner 可 promotion。

audit 至少记录 discovery、authorization、caller/nesting、execution locus、start/terminal、network/retrieval/runtime
receipt、usage、cleanup、cancel/fence 和 bounded artifact refs。Secret、raw unrestricted output、browser cookie、signed
URL、provider capability token 和完整 external body 不进入普通 trace。

## 12. Security 与 fail-closed matrix

| 风险                             | 必须行为                                                                   |
| -------------------------------- | -------------------------------------------------------------------------- |
| hidden Provider tool             | 无 exact descriptor/call receipt 即拒绝；不能用于 apply                    |
| dynamic tool expansion           | 只在 frozen registry 内；新 descriptor 需要新 admission/grant              |
| programmatic opaque nested calls | 仅 side-effect-free bounded read；其他 capability disabled                 |
| malicious tool metadata/result   | strict schema + data-only；不能改变 policy、grant、approval                |
| retrieval poisoning              | source authority/provenance保留；instruction不跟随                         |
| stale/provider file index        | blocked/omitted；不能用于 current target proposal                          |
| cross-project memory/index       | 禁止；tenant/workspace scope 与 deletion不可证则 disabled                  |
| hosted code escape               | isolated runtime、no ambient Secret/network/write；cleanup residual 为失败 |
| computer-use authoring           | 禁止；只能 verification/read-only disposable session                       |
| arbitrary MCP                    | 未 pin publisher/version/digest/schema/auth 即 disabled                    |
| parallel effect conflict         | canonical stage/join/owner planner；未知 commutativity 串行                |
| managed-agent hidden delegation  | explain/read admission-only；无 proposal/apply authority                   |
| fake tool test/approval          | 无 G3/approval authority；记录 injection attempt                           |

## 13. 拒绝的方案

### Provider built-in tool 自动可信

拒绝。执行位置和 Provider 品牌不改变 effect、数据披露、授权、预算或审计要求。

### tool search 可以发现 registry 外任意工具

拒绝。它把描述文本变成动态 capability grant，并使 approval 无法绑定 exact tool set。

### 用 Provider vector store 作为项目记忆真相

拒绝。它没有 Workspace revision、Command/History、迁移、可逆写入和跨 Provider portability。

### 用 computer use 点击编辑器来避免实现 domain action

拒绝。这是 alternate Workspace write path，无法稳定绑定 target、Transaction、Impact 和 rollback。

### opaque managed agent 作为一个普通 tool call

拒绝。隐藏的 delegation/tool/state/retry 无法满足逐调用授权、预算和 fencing。
