## 背景

G2 已有Browser/Remote Test、Vitest canonical report、React/Vue export、Browser/Remote Preview、build和Chrome product Gate。
G3需要把unit/integration/E2E/visual/accessibility/performance/security结果放进同一Plan/Evidence体系，并证明同一
BehaviorScenario在Preview、Export和CI运行。若Web直接理解Playwright/axe/Vitest私有JSON，或每个target维护自己的
Scenario脚本，G2建立的provider-neutral边界会失效。

## 决策

### Adapter registry

`@prodivix/verification`定义internal controlled adapter contract：

```ts
type VerificationAdapterDescriptor = Readonly<{
  id: string;
  implementation: VerificationImplementationIdentity;
  checkKinds: readonly VerificationCheckKind[];
  surfaces: readonly ('preview' | 'export' | 'ci')[];
  targets: readonly string[];
  browserEngines: readonly ('chromium' | 'firefox' | 'webkit')[];
  controlCapabilities: readonly string[];
  inputKinds: readonly VerificationInputKind[];
  artifactKinds: readonly VerificationArtifactKind[];
  budgets: VerificationAdapterBudgets;
  trustInputs: readonly string[];
}>;
```

**能力声明只有一处，且必须可枚举。** descriptor 的数组既是 planner 展开 matrix 的依据，也是进入
registry snapshot digest 的字节。不存在 `VerificationCapabilityPredicate` 之类的谓词能力声明 ——
谓词进不了 digest，也无法确定性展开，会直接击穿 ADR 57 的「Plan ID 由 canonical normalized input digest 派生」。
adapter 声明了却在运行期跑不了的 cell，走正常 cell 状态报 `blocked`/`unsupported`，不设第二套能力判定机制。

`checkKinds` 是复数数组：一个 adapter 真实地同时服务多个 kind（如 Playwright 覆盖 e2e、visual、accessibility）。
不存在与之并列的 `VerificationCheckFamily` 概念。

### Adapter 生命周期与信任边界

Adapter 接收 immutable Plan cell、Scenario Program、Executable Snapshot/artifact refs、control profile 和 abort signal，
按 `preflight → prepare → execute → cleanup` 生命周期执行。current adapter-facing SPI 的核心公开签名如下；factory 只获得已规范化
descriptor/identity/tool、runtime zone 与 registry snapshot digest，`prepare` 才获得 Core 解析、校验并 digest-bound
的本次运行 context：

```ts
type VerificationAdapterLifecycleContext = Readonly<{
  registrySnapshotDigest: string;
  adapter: VerificationAdapterIdentity;
  runtimeZone: string;
  runtimeEnvironmentDigest: string;
  inputDigest: string;
  executableSnapshotDigest: string;
  scenarioProgramDigest?: string;
  controlProfileDigest: string;
  fixtureSetDigests: readonly string[];
  baselineSetDigest?: string;
  controlCapabilityIds: readonly string[];
  controlCapabilitySnapshotDigest: string;
  appliedControlDigest: string;
  inputRefs: readonly VerificationAdapterInputRef[];
  inputResolver: VerificationAdapterInputResolver;
  artifactStaging: VerificationAdapterArtifactStagingTransportPort;
  abortSignal: VerificationAbortSignal;
}>;

type VerificationAdapterContext = Omit<
  VerificationAdapterLifecycleContext,
  'artifactStaging' | 'inputResolver' | 'abortSignal'
> &
  Readonly<{
    resolvedInputSetDigest: string;
    inputResolver: VerificationAdapterInputResolver;
    artifactStaging: VerificationAdapterArtifactStagingPort;
    abortSignal: VerificationAbortSignal;
  }>;

type VerificationAdapterPrepareInput = Readonly<{
  planDigest: string;
  cell: VerificationPlanCell;
  attemptId: string;
  generation: number;
  providerKind: 'browser' | 'remote' | 'export' | 'ci' | 'local';
  controlCapabilitySnapshotDigest: string;
  appliedControlDigest: string;
  context: VerificationAdapterContext;
}>;

type VerificationAdapterCleanupInput = Readonly<{
  planDigest: string;
  cellId: string;
  attemptId: string;
  generation: number;
  cause:
    | 'success'
    | 'preflight-failed'
    | 'prepare-failed'
    | 'execute-failed'
    | 'cancelled'
    | 'timed-out';
  invocation?: PreparedVerificationInvocation;
  abortSignal: VerificationAbortSignal;
}>;

type VerificationAdapterFactoryContext = Readonly<{
  descriptor: VerificationAdapterDescriptor;
  identity: VerificationAdapterIdentity;
  tool: VerificationAdapterToolIdentity;
  runtimeZone: string;
  registrySnapshotDigest: string;
}>;

type VerificationAdapterFactory = (
  context: VerificationAdapterFactoryContext
) => VerificationAdapter;

type VerificationAdapter = Readonly<{
  preflight(
    cell: VerificationPlanCell,
    context: VerificationAdapterContext
  ): Promise<VerificationAdapterPreflight>;
  prepare(
    input: VerificationAdapterPrepareInput
  ): Promise<VerificationAdapterPreparedInvocationCandidate>;
  execute(
    invocation: PreparedVerificationInvocation,
    sink: VerificationEventSink
  ): Promise<VerificationCheckReportCandidate>;
  cleanup(
    input: VerificationAdapterCleanupInput
  ): Promise<VerificationAdapterCleanupResult>;
}>;
```

Core 是 adapter lifecycle 的唯一进程内 authority：同一 attempt generation 只允许一个 concurrent
single-flight；resolved input、event sequence 与 artifact staging 都绑定 exact
`planDigest/cellId/attemptId/generation`，cleanup 后对应 generation 的 staging/event port 永久
`rejected`。registered first-party adapter 的 `cleanup` 是 terminal acknowledgement，不是“已请求清理”；
任意 detached JavaScript timer、late promise 或 cleanup 后回调都不能再变成可追溯 event/artifact/result。
composition root 调用 `executeVerificationAdapterLifecycle` 时还必须传入 exact registry snapshot、Plan/cell、
attempt/generation/provider 与 Core-owned `VerificationAdapterArtifactRetirementPort`；失败路径用该 port 原子关闭
generation 并清除该 attempt 已写入、包括 late receipt 尚未暴露的 staging objects。

跨进程或序贯重试的 exact-once 不由内存中的 generation 冒充：现有 PostgreSQL AttemptGrant 使用
`UNIQUE(workspace, plan, cell, attempt)` 与一次性 claim authority 仲裁。generation 是 attempt 内运行时 fence，
不进入 V5 Evidence wire，也不改变 append-only Evidence identity。

**normalization 属于 Core，不属于 adapter。** `execute` 的产物是 bounded `VerificationCheckReportCandidate` ——
adapter 的受限原始输出，未经信任。由 `@prodivix/verification` Core 独家负责 strict normalization、identity、
budget、SourceTrace 与 `VerificationEvidenceCandidate` 构造，再交给 ADR 58 的 Evidence intake。

这条边界不能让步：adapter 是扩展点，若 normalization 落在 adapter 内，Evidence 的可信度就变成
O(adapter 数量)，而 ADR 58 的 intake gate 会从「规范化原始输出」退化成「复核 adapter 的自述结果」。
`VerificationCheckReportCandidate` 与 `VerificationEvidenceCandidate` 是两个信任级别不同的类型，
各有单一 owner，其转换 owner 由 ADR 58 定义。Web/Backend 不解析工具私有 payload。

G3 registry只开放first-party/controlled adapters，不承诺public SDK、第三方plugin或Marketplace；这些属于G6。

### Check families

#### Diagnostics/build/unit/integration

- diagnostics消费exact Semantic/Compiler/Workspace diagnostic snapshot；
- build复用G2 Build ExecutionJob和artifact digest；
- unit/integration消费canonical `ExecutionTestReport`，Vitest私有JSON仍由`@prodivix/runtime-vitest`转换；
- report file/case映射到stable check id与SourceTrace，大量原始详情作为artifact。

单个G2 report不是Evidence。Verification adapter必须补齐Plan/check/snapshot/tool/provenance并通过Evidence intake。

#### E2E/Behavior

Browser scenario driver消费同一`BehaviorScenarioProgram`。target定位优先使用accessible role/name、Route/public contract和
opaque semantic target id；禁止把CSS/XPath保存回Scenario。

Black-box observation（URL、accessible state、DOM-visible behavior、network metadata、screenshot）是跨surface closure的
主要证明。verification-only white-box probe只提供sanitizeddomain trace/SourceTrace诊断增强：

- probe由Compiler从同一ExportProgram生成；
- 只在verification/test profile激活；
- 没有Workspace/network/Secret/write capability；
- production artifact必须通过hard-cut检查确认未包含probe control endpoint；
- white-box trace不能成为唯一passed依据。

#### Visual

Visual adapter在controlled browser image、font、viewport、DPR、color/motion和observation settle下capture PNG。Baseline
compatibility key至少包含Scenario/step、target、browser engine、OS/image、font set、viewport/DPR、color/motion和
renderer generation。

结果记录exact baseline/current/diff digest、changed pixel/region summary、threshold和mask/exemption。React/Vue或不同engine可
使用不同baseline，但共享semantic assertion；不能以跨framework像素完全相同作为行为parity。

Mask必须绑定stable semantic target/region并经Policy审阅，不能在failure后自动扩大。Baseline 必须在 attempt
开始前已通过 Workspace Transaction 采纳，并由 content digest 与 OS/browser/font/viewport/DPR/color/motion/
renderer compatibility identity 绑定；不得用本次 current screenshot 在同一 run 内临时生成“baseline”后自比。Baseline
update 产生新的 Workspace Transaction。

CI `runs-on` label 不是可比较的 OS identity。V6 workflow 固定 `ubuntu-24.04`，adapter 还必须读取并 exact
匹配预采纳 registry 中的 GitHub runner `ImageVersion`；缺失、未知或漂移的 image 只能 blocked，不得把泛化的
“Ubuntu 24.04”字符串当作 visual/performance compatibility evidence。

#### Accessibility

Accessibility adapter将工具私有finding转换为canonical rule id、impact、target、message key、SourceTrace和bounded related node。
至少覆盖accessible name/role/state、focus order/trap、keyboard path、landmark/heading、contrast和dynamic announcement。raw DOM片段
不进入manifest；需要时以受控artifact保存。

Policy exemption保留raw finding与applied reason/expiry。跨engine规则结果按adapter schema compatibility比较。

#### Performance

Performance检查使用controlled environment采集navigation/interaction、resource、layout shift、long task、animation frame和
scenario duration aggregate。它验证声明budget，不把本机偶然毫秒差异当作跨环境回归。Evidence记录machine/image/browser/
warm-cache class和sample strategy；不兼容环境不做trend。

#### Security

Security Evidence 固定为九个不可替代、不可豁免的 hard-rule observation；owner 与产生时序如下：

| 阶段                                 | Owner                            | 固定 observation                                                                                                                          |
| ------------------------------------ | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Browser runtime                      | `@prodivix/verification-browser` | `security.unexpected-network`、`security.csp-policy`、`security.permissions-policy`、`security.sandbox-isolation`                         |
| G2 execution Secret scanner input    | `@prodivix/runtime-core`         | `security.secret-canary`                                                                                                                  |
| G2 full production bundle scan input | `@prodivix/prodivix-compiler`    | `security.production-probe-leak`                                                                                                          |
| G2 output artifact inspector input   | `@prodivix/runtime-core`         | `security.output-artifact-uninspectable`                                                                                                  |
| Core finalization                    | `@prodivix/verification`         | successful artifact staging 后的 `security.artifact-digest-drift`、terminal `cleanup.status === "clean"` 后的 `security.cleanup-residual` |

Browser adapter 必须先将四个 browser-owned observation 与三个经 source digest、attempt binding 和 authority
re-resolution 校验的 G2 observation 合成 **exact seven-rule pre-finalization report**。它不能生成或替代两个
Core-finalization rule。Core 只有在所有 artifact descriptor 与 staged bytes 的 digest/size/media type exact match、
staging 成功、transport drain 完成、terminal port 无 late write 且 cleanup clean 后，才补齐两个零违规 observation，
并重新用 public strict decoder 验证 **exact nine-rule report**；任一环节失败都停止 candidate/Evidence 路径。
network/header/sandbox 等 browser-owned observation 必须来自 browser/provider trusted boundary；page author 对
`window`、DOM prototype、frame element 或公开 collector 的 monkeypatch 不能伪造 observation 或把 blocked 变成 passed。

G3 不重新实现 G2 scanner。`security.production-probe-leak` 必须来自 Compiler 对 exact full production
bundle/source manifest 的扫描；`page.content()`、当前渲染 DOM、单个入口文件或运行时可见文本都不是完整 production
artifact，不能满足 probe-stripped rule。Secret/canary 命中、unexpected network、production probe 泄漏、artifact
digest drift、不可检查 output 或 cleanup residual 均为不可豁免 required failure。

### Surface与target matrix

稳定surface语义：

- `preview`：Editor Browser/Remote Preview，由本地或受控remote provider运行；
- `export`：从exact ExportProgram构建的standalone app/bundle，在独立browser/runtime运行；
- `ci`：非交互受控runner执行canonicalPlan，产生attested Evidence。

surface不是framework target。React/Vite与Vue/Vite必须消费相同Scenario/current domain；adapter capability差异在Plan中显式。

G3 Golden matrix采用风险分层，避免无界笛卡尔积：

| 范围                          | 必须覆盖                                                                            |
| ----------------------------- | ----------------------------------------------------------------------------------- |
| 所有critical Scenario         | Preview、Export、CI；primary engine；full/reduced（若有motion）                     |
| Authenticated Catalog CRUD    | React/Vite与Vue/Vite；loading/empty/error/retry/pagination/optimistic/mutation/auth |
| Cross-browser critical subset | Chromium、Firefox、WebKit的black-box semantic/a11y                                  |
| Visual baseline observations  | controlled compatibility cells，不要求跨target同baseline                            |
| Impacted code/domain          | unit/integration/build/diagnostics与policy-selected security/performance            |

每个cell独立报告unsupported/blocked；不能用一个target通过替代另一个required target。

当前 controlled Golden 固定为 66 个 required Plan cells、8 个 aggregate rows 与 80 个实际 attempts：58 个
browser-family cells 产生 72 个 attempts，另有 8 个 static-family attempts；其中 Preview 的 14 个 cells 必须分别经
Browser 与 Remote provider 执行，两种 provider 是同一 cell 的 attempt 维度，不重复扩张 Plan。Remote attempt 必须经过
`@prodivix/runtime-remote` 的 execution/control-plane、exact bundle materialization、readiness 与 cursor lifecycle；
只把 `providerKind` 写成 `remote`、再经 in-memory echo transport 返回结果，不构成 Remote evidence。
Data（loading/empty/error/retry/pagination/optimistic conflict）、Auth（signed-out/signed-in/expired/denied/
authorized function）与 Recovery（cancel/timeout/worker loss/cursor resume/duplicate/out-of-order）是 Scenario
内部的 controlled profiles，不是继续乘到 66 cells 上的新 Plan axis。每个 profile 仍必须由
`verify:g3:adapter-matrix` 直接重跑的 exact owner test/manifest 证明；旧 V2/V3 Gate 只能作为回归背景，不能替代 V6
本次证据。
该 companion manifest 由 `@prodivix/golden-conformance` 单一拥有，固定列出 profile → owner suite → exact case title
映射；runner 必须验证所有指定 case 和所选文件的全部 test 均 passed，拒绝 failed/skipped/todo，并输出
content-addressed manifest digest。

### Tool identity与private payload

Adapter固定tool name/version、adapter schema version和normalized capability。私有JSON、browser handle、page object、SDK error、
absolute temp path和vendor URL不越过adapter。unknown field、oversized report、partial result和terminal-after-report drift fail closed。

Tool upgrade造成normalization或baseline compatibility变化时显式使历史comparison incompatible；不能悄悄复用旧baseline。

Golden conformance 当前使用 AJV runtime schema compile，因此受控 Golden CSP 基线显式允许
`unsafe-eval`，并以独立固定 digest 进入 identity。Browser security cell 运行同一 Golden production output；
V6 在这里证明的是声明策略 exact、digest-bound 且不会被静默放宽，**不宣称 hardened production CSP**。
移除 `unsafe-eval` 需要 Compiler 预编译 AJV validator 后另行收口，不能伪造为当前已完成。

### Failure classification

规范化结果区分：

- assertion/finding failure；
- product diagnostic/build failure；
- unsupported capability；
- fixture/control failure；
- adapter/tool infrastructure error；
- cancellation/timeout；
- malformed/unsafe candidate。

只有第一类及受支持的policy finding属于产品失败；基础设施失败可有界重试但不能变成assertion passed。所有类别都能定位
Plan cell/check与适用的SourceTrace。

## 拒绝的方案

### Web直接解析Playwright/axe/Vitest结果

拒绝。工具schema会扩散，Remote/CI与未来adapter无法共享产品表面。

### 每个framework复制Scenario

拒绝。target adapter只负责projection；Scenario identity和semantic assertions共享。

### 为视觉一致强制React/Vue同一pixel baseline

拒绝。行为/可访问性应一致，framework/engine raster差异由compatibility cell管理。

### verification probe进入production

拒绝。production hard-cut必须证明控制endpoint、fixture和white-box bridge不存在。

## 后果

- 新建Verification Core和Browser adapter；受控Playwright/axe/image/performance adapter在private边界转换。
- Runtime/Compiler/Remote Worker需要verification profile和production probe hard-cut。
- G2 canonical reports/artifacts成为Evidence输入而非被替代。
- Golden conformance扩展为Scenario×surface×target×control matrix。

## 验收

- [x] 所有tool private payload在adapter边界转换，Core/Web只见canonical candidate/report。
- [x] black-box proof跨Preview/Export/CI，white-box probe仅作诊断且production hard-cut。
- [x] visual baseline compatibility/mask/update、a11y finding/exemption和performance环境比较稳定。
- [x] Secret/network/CSP/sandbox安全结果进入不可豁免Evidence Gate。
- [x] React/Vue与三browser critical subset使用同一Scenario并有独立required cell。
- [x] unsupported、partial、oversized、tool drift和infrastructure failure不会伪装passed。
- [x] controlled Golden 逐一执行 66 required cells / 8 rows / 80 attempts，全部产生 Core-normalized
      `passed` report，且 blocked/unsupported/skipped/failed/residual 均为零；6 个 target/engine smoke 不能替代。
- [x] 每个 attempt evidence 绑定 cell/provider、report digest、resolved input-set digest、artifact digests 与 clean
      cleanup；aggregate digest 同时绑定 Plan、matrix/browser identity/baseline registries 与逐-row counts。
- [x] 每个 browser attempt 同时绑定 deterministic runtime-control 的 initial 与 terminal same-context
      attestation；terminal attestation 必须证明 exact attempt/context、零 residual，cleanup release receipt 进入
      aggregate evidence，不能只记录 start-time control digest。
- [x] 每个 static attempt 的 artifact retirement receipt 进入 aggregate evidence，且 static transport
      `activeAttemptCount` / `activeArtifactCount` 均为零；进程退出或全局 cleanup 不能替代逐-attempt retirement。
- [x] 14 个 Preview Remote attempts 均绑定 control-plane execution、exact snapshot/bundle/materialization digest、
      ready/healthy、resume/terminal cursor 和 cleanup/retirement evidence；echo transport 不计入。
- [x] `VerificationCoverageSummary`、`VerificationBuildSummary` 与 `VerificationTrace` 三类 canonical artifact
      projection 均证明 adapter/tool-private path 与私有 payload 已在 owner 边界移除；absolute path、URL、
      vendor field、raw tool locator 与 canary 不得进入 staged canonical bytes、Core/Web 或 Evidence。
- [x] Scenario-internal Data/Auth/Recovery companion manifest 精确覆盖 17 个 profiles、8 个 owner suites 与
      28 个指定 cases，所选文件 failed/skipped/todo 均为零。
- [x] 本地 Gate 通过只允许标记 `Implemented locally / CI Evidence pending`；取得固定 commit、workflow run 和
      target environment identity 后才升级 durable CI evidence，且仍不代表 V7/V8 或 Global G3 Passed。
