本文冻结 Provider/model 能力、一次 inference invocation、Provider-side state、上下文转换、异步 job 与 usage
的 current domain。外部 API 的字段、事件名和 preview 状态不是 Prodivix current model；adapter 只在 wire 边界
消费它们并归一到本文 contract。

## 背景

现代 AI Provider 已不只是返回文本的同步 HTTP endpoint。一次请求可能组合 structured output、reasoning、
client-hosted tool、Provider-hosted tool、缓存、server-side continuation、后台执行和多种输入输出 modality。
若只记录 `provider + model + token count`，无法回答：

1. 实际启用了哪一组能力，哪一组真正通过 release evaluation；
2. Provider 是否保存、裁剪、压缩、缓存或静默补充了上下文；
3. tool loop 继续所需的 opaque state 是否被误当作可审计 reasoning；
4. background callback、重试与取消是否仍属于当前 Run generation；
5. fine-tune、推理参数、本地 runtime 或 mutable alias 改变后旧 Evidence 是否仍有效；
6. 图片、音频、检索、代码执行和存储费用如何进入同一个硬预算。

G4 因而把 Provider 视为受策略约束的 subordinate inference execution plane，而不是 authority。Provider 可以计算，
但不能拥有 AgentTask、Capability Grant、Proposal、Approval、Workspace write 或 Verification truth。

## 决策摘要

一次 production-eligible invocation 必须绑定：

```text
Provider protocol + adapter
  + provider operator / exact endpoint profile
  + model lineage / immutable-or-unknown version
  + typed capability profile
  + inference configuration
  + Context Pack / effective-context receipts
  + state/cache/delivery mode
  + policy/grant/budget/generation
  -> normalized events + usage vector + immutable receipt
```

支持状态的判断单位不是整个 Provider 或 model alias，而是：

```text
provider configuration × model configuration × capability profile × policy profile
```

任何未声明、未探测、未授权或未评测的 capability 都不能继承其他 slice 的 `release-evaluated` 状态。

## 1. Provider、model 与 adapter identity

```ts
type AgentProviderProtocolFamily =
  | 'openai-responses'
  | 'anthropic-messages'
  | 'gemini-interactions'
  | 'openai-compatible';

type AgentProviderSupportTier =
  'release-evaluated' | 'admission-only' | 'disabled';

type AgentProviderAdapterIdentity = Readonly<{
  adapterId: string;
  adapterVersion: string;
  adapterDigest: CanonicalDigest;
  protocolFamily: AgentProviderProtocolFamily;
  transportSchemaDigest: CanonicalDigest;
  eventNormalizationDigest: CanonicalDigest;
}>;

type AgentProviderConfigurationIdentity = Readonly<{
  providerConfigurationId: string;
  providerOperatorId: string;
  endpointClass: 'first-party-hosted' | 'aggregator' | 'self-hosted' | 'local';
  endpointProfileDigest: CanonicalDigest;
  providerRegion?: string;
  apiRevision?: string;
  adapter: AgentProviderAdapterIdentity;
  dataPolicyDigest: CanonicalDigest;
}>;

type AgentModelLineage = Readonly<{
  modelId: string;
  modelFamilyId: string;
  modelFamilyOwnerId: string;
  immutableVersion?: string;
  baseModelRef?: AgentModelRef;
  fineTuneRef?: AgentFineTuneRef;
  tokenizerDigest?: CanonicalDigest;
  chatTemplateDigest?: CanonicalDigest;
  quantizationDigest?: CanonicalDigest;
  runtimeBackendDigest?: CanonicalDigest;
}>;
```

- alias 不是 immutable identity；无法取得 vendor version 时明确记录 `unknown`，并使用更短 Evidence freshness；
- fine-tune 必须绑定 base model、fine-tune job/deployment、训练策略与允许披露的数据 lineage digest；不得记录训练
  数据正文；
- self-hosted/local model 的 tokenizer、chat template、quantization、runtime backend 任一变化都属于行为 identity
  drift；
- aggregator 的 operator、上游 model family owner 和 protocol adapter 分别记录，不能用 endpoint alias 混为一体；
- region、API revision、safety policy 或服务等级会改变行为/数据处理时必须进入 endpoint 或 invocation identity。

## 2. Typed capability profile

`capabilityDigest` 不能只是 Provider 自报的 opaque string。`@prodivix/ai` 拥有可枚举的 current profile：

```ts
type AgentCapabilityProfile = Readonly<{
  profileId: AgentCapabilityProfileId;
  inputModalityRefs: readonly AgentModalityProfileRef[];
  outputModalityRefs: readonly AgentModalityProfileRef[];
  outputContracts: readonly ('text' | 'structured' | 'tool-call')[];
  toolExecutionLoci: readonly AgentToolExecutionLocus[];
  deliveryModes: readonly (
    'response' | 'stream' | 'background' | 'realtime-session'
  )[];
  providerStateModes: readonly AgentProviderStateMode[];
  contextMutationModes: readonly AgentContextMutationMode[];
  reasoningModes: readonly AgentReasoningMode[];
  featureFlags: readonly AgentCapabilityFeature[];
  hardLimits: AgentCapabilityLimits;
  profileDigest: CanonicalDigest;
}>;

type AgentCapabilityQualification = Readonly<{
  provider: AgentProviderConfigurationIdentity;
  model: AgentModelLineage;
  capabilityProfileDigest: CanonicalDigest;
  policyProfileDigest: CanonicalDigest;
  declaredCapabilityDigest: CanonicalDigest;
  probedCapabilityDigest: CanonicalDigest;
  evaluationManifestRef?: AgentModelEvaluationManifestRef;
  supportTier: AgentProviderSupportTier;
  evaluatedAt: Instant;
  expiresAt: Instant;
  qualificationDigest: CanonicalDigest;
}>;
```

有效能力是下列集合的交集：

```text
adapter implemented
  ∩ endpoint declared
  ∩ active capability probe
  ∩ effective AgentPolicy
  ∩ Task/Run grant
  ∩ non-expired evaluation qualification
```

规则：

1. `release-evaluated` 只授予 exact qualification，不授予整个 Provider 品牌或 model family。
2. 未评测的 visual、document、hosted retrieval、background、realtime 或 computer-use slice 保持
   `admission-only`/`disabled`，不能继承 text slice 结论。
3. Provider 自报 capability 只能作为 admission 输入；active probe 与 conformance fixture 才证明 wire 行为。
4. probe 不能发送 Workspace Secret 或生产数据；probe 结果带 endpoint/model/API revision 与 expiry。
5. capability 未知、限制未知或 probe/声明冲突时 fail closed；不得自动 fallback 到另一个模型或低保真模式。
6. optional profile 不支持不会使已经独立通过的 core profile 失效；但宣称该 optional profile 可用时必须单独 qualification。

G4 required core profile 至少包含 bounded text/code input、structured output、client-hosted typed tool calling、
streaming、stateless invocation、refusal/truncation normalization。视觉与文档 required profile 由 ADR 67 冻结；
Provider-hosted capability profile 由 ADR 68 冻结。

## 3. Invocation configuration identity

```ts
type AgentInferenceConfiguration = Readonly<{
  temperature?: number;
  topP?: number;
  seed?: number;
  maxOutputUnits: AgentUsageLimit;
  reasoningMode: AgentReasoningMode;
  reasoningBudget?: AgentUsageLimit;
  outputSchemaDigest: CanonicalDigest;
  promptPolicyDigest: CanonicalDigest;
  toolRegistryDigest: CanonicalDigest;
  toolChoicePolicy: AgentToolChoicePolicy;
  parallelToolPolicy: AgentParallelToolPolicy;
  providerStateMode: AgentProviderStateMode;
  contextMutationMode: AgentContextMutationMode;
  cacheMode: AgentProviderCacheMode;
  deliveryMode: 'response' | 'stream' | 'background' | 'realtime-session';
  safetyPolicyDigest?: CanonicalDigest;
  serviceTier?: string;
  configurationDigest: CanonicalDigest;
}>;
```

- 未被 Provider 支持的参数省略并记录，不发送伪兼容字段；
- Provider 默认值会影响行为时 adapter 必须 materialize 到 sanitized request receipt，不能只依赖 ambient default；
- seed 存在也不代表确定性；它只是 identity，真实稳定性仍由 ADR 69 的 repetition 证明；
- reasoning summary、自报 confidence 或自然语言 rationale 都是 untrusted model output，不是 authorization/audit proof；
- mutable safety policy、service tier 或推理模式 drift 会使对应 evaluation slice expired。

## 4. Provider state、opaque continuation 与 ambient memory

```ts
type AgentProviderStateMode =
  | 'stateless'
  | 'provider-stored-parent'
  | 'provider-background-job'
  | 'realtime-session';

type AgentOpaqueContinuationRef = Readonly<{
  continuationId: AgentOpaqueContinuationId;
  encryptedBlobRef: EncryptedArtifactRef;
  providerConfigurationId: string;
  modelLineageDigest: CanonicalDigest;
  taskId: AgentTaskId;
  runId: AgentRunId;
  generation: number;
  parentInvocationId: AgentInvocationId;
  purpose: 'provider-tool-loop-continuation';
  createdAt: Instant;
  expiresAt: Instant;
  continuationDigest: CanonicalDigest;
}>;
```

raw private reasoning/chain-of-thought 不进入普通 event、trace、Context Pack 或 Evidence。若 native protocol 要求
原样回传 encrypted thinking/signature/continuation block，adapter 可以保存 `AgentOpaqueContinuationRef`，但：

- 内容不被解析、展示、索引或当作 rationale；
- 只能回传给同一 provider configuration、model lineage、Task/Run/generation 与直接 parent invocation；
- 使用 encrypted、role-restricted、short-retention store；terminal/cancel/expiry 后删除并保存 deletion receipt；
- 不能跨 Task、跨 model、跨 Provider、跨 repair generation 重放；
- 无法界定来源、生命周期或删除语义时，该 capability 不得用于 apply-capable Run。

Provider-side conversation state 不是 Workspace、Context 或 AgentRun truth。默认 `stateless`/storage-disabled；
显式启用 parent state、background job 或 realtime session 时，exact parent ref、storage mode、region、retention、
training、deletion policy 与 receipt 必须进入 invocation identity。

Provider ambient memory、personalization、跨会话 profile 和跨项目历史默认关闭。若无法关闭或证明隔离：

- 不能处理受限 Context；
- 不能形成长期 release evidence；
- 不能用于 production apply；
- 不得把隐藏记忆输出解释成 Workspace source。

## 5. Effective context、cache 与 Provider-side transformation

本地 `AgentContextPack.manifestDigest` 证明 Prodivix 提交了什么，但 Provider 可能执行 cache、compaction、context
editing、tool-result trimming 或 deferred tool expansion。必须另外保存：

```ts
type AgentContextTransformReceipt = Readonly<{
  invocationId: AgentInvocationId;
  submittedContextPackDigest: CanonicalDigest;
  transformMode: AgentContextMutationMode;
  transformConfigurationDigest?: CanonicalDigest;
  retainedItemDigests?: readonly CanonicalDigest[];
  omittedOrCompacted?: readonly AgentContextTransformOmission[];
  effectiveContextDigest?: CanonicalDigest;
  confidence: 'verified' | 'provider-reported' | 'unknown';
  receiptDigest: CanonicalDigest;
}>;

type AgentProviderCacheReceipt = Readonly<{
  cacheMode: AgentProviderCacheMode;
  cacheScope: 'invocation' | 'task' | 'workspace';
  cacheKeyDigest?: CanonicalDigest;
  prefixOrItemDigests: readonly CanonicalDigest[];
  providerRegion?: string;
  createdAt?: Instant;
  expiresAt?: Instant;
  usageRef: AgentUsageVectorRef;
  receiptDigest: CanonicalDigest;
}>;
```

- G4 禁止跨 workspace 或跨 tenant cache；
- cache hit 降低 billable usage，不减少 logical context volume；
- automatic compaction/truncation 未产生可解释 receipt 时，proposal 必须标记 Context incomplete；Policy 决定
  blocked 或只允许 explain；
- Provider 自动展开 deferred tools 时，exact expanded descriptor digest 进入 effective-context receipt；
- context transform 不能提升 item authority、恢复已省略 Secret 或把外部内容放进 system/developer instruction boundary；
- prompt cache、file cache 和 conversation state 是不同对象，不能用同一个 `cached: true` 混淆。

## 6. Provider job 与异步 delivery

```ts
type AgentProviderJobPhase =
  'submitting' | 'accepted' | 'running' | 'cancelling' | 'terminal';

type AgentProviderJobOutcome =
  'completed' | 'failed' | 'cancelled' | 'expired' | 'reconciliation-required';
```

Provider job 是 invocation 的 subordinate service state，不是第二个 `AgentRun`。生命周期必须满足：

1. submit 使用 invocation idempotency key，保存 sanitized request digest 与 Provider job reference；
2. poll/webhook/stream event 都绑定 `taskId + runId + generation + invocationId + providerJobId`；
3. webhook 验证来源、签名、timestamp/replay window、payload digest 和 current generation；
4. cancel 先 revoke callback authority，再调用 Provider cancel；late completion 只记审计，不进入 Context/Proposal；
5. Provider terminal 不等于 Run success，仍需 decode、usage settle、proposal/approval/verification；
6. timeout、进程重启或 ACK 丢失后按 job identity reconcile，不能盲目重复 submit；
7. background mode 要求的 storage/retention/deletion 必须在 capability qualification 和 Policy 中显式允许；
8. Provider 无法证明 terminal usage 时按预留上界结算或进入人工 reconciliation，不能记零成本。

Realtime session 共享相同 generation fence，但媒体/session 语义由 ADR 67 进一步约束。

## 8. Usage vector、pricing 与 hard budget

Token 只是 usage 的一种单位：

```ts
type AgentUsageUnit =
  | 'text-token-input'
  | 'text-token-output'
  | 'reasoning-token'
  | 'cache-read-token'
  | 'cache-write-token'
  | 'image'
  | 'image-pixel'
  | 'document-page'
  | 'audio-second'
  | 'video-second'
  | 'video-frame'
  | 'hosted-search-query'
  | 'hosted-tool-call'
  | 'sandbox-compute-second'
  | 'provider-storage-byte-second';

type AgentUsageAmount = Readonly<{
  unit: AgentUsageUnit;
  logicalAmount?: DecimalString;
  billableAmount?: DecimalString;
  cachedAmount?: DecimalString;
  confidence: 'reported' | 'measured' | 'estimated' | 'unknown';
  sourceDigest?: CanonicalDigest;
}>;

type AgentUsageVector = Readonly<{
  amounts: readonly AgentUsageAmount[];
  vectorDigest: CanonicalDigest;
}>;
```

`AgentBudget` 同时限制 usage vector、model invocation、tool call、repair、transaction、artifact bytes、elapsed time
和 currency cost。ledger 规则继承 ADR 65：并发前原子 reserve，结束后 settle；crash 后按保守上界或人工
reconciliation；任何维度耗尽即 blocked，不自动换模型、减少 required evaluation 或关闭证据记录。

- logical、billable、cached、estimated/unknown 分别记录；
- Provider pricing 必须绑定 currency、unit price、tier、region、effective instant 与 source digest；
- unknown usage 不伪造为零；Policy 可直接拒绝无法硬限制的 capability；
- budget 是 authorization ceiling，不是模型可请求扩大或通过 prompt 修改的参数；
- ADR 69 的 evaluation budget 使用相同 usage vector，不能只设置 token 上限。

## 9. Protocol matrix 与 normalization

G4 baseline 独立实现并验证：

1. deterministic `scripted` provider：仅用于 conformance/failure injection，不计 production Provider diversity；
2. `openai-responses` native adapter；
3. `anthropic-messages` native adapter；
4. `gemini-interactions` native adapter；
5. `openai-compatible` generic adapter：compatibility tier，按 exact hosted/local endpoint profile admission。

Native transport 参考分别为 [OpenAI Responses API](https://platform.openai.com/docs/api-reference/responses)、
[Claude Messages API](https://platform.claude.com/docs/en/api/messages) 与
[Gemini Interactions API](https://ai.google.dev/gemini-api/docs/interactions-overview)。这些页面会变化；
Prodivix 只冻结 adapter version/digest、transport fixtures 与 qualification 所消费的 exact 语义。

所有 production-eligible adapter 使用同一 conformance matrix归一：

- role、content block、stream ordering、incremental arguments、parallel tool-call、finalization；
- structured output、refusal、safety block、stop/truncation；
- reasoning/continuation block、state/cache/context transform；
- response/stream/background/realtime delivery；
- usage vector、pricing、rate limit、retry-after、error、cancel、timeout 和 partial result；
- region、retention、training、residency 与 capability declaration。

unknown enum/state/capability 一律 fail closed。generic OpenAI-compatible 没有单一权威规范；一处兼容不能外推到
所有端点，hosted 与 local/self-hosted 也必须分别 admission。

## 10. Security 与 fail-closed matrix

| 风险                          | 必须行为                                                                               |
| ----------------------------- | -------------------------------------------------------------------------------------- |
| capability inheritance        | qualification 按 exact slice；未评测能力不继承 `release-evaluated`                     |
| mutable model/default drift   | identity mismatch；proposal/evaluation slice expired                                   |
| hidden provider state         | 默认 stateless；未知 parent/memory/storage 使 apply blocked                            |
| opaque reasoning exfiltration | encrypted callback-bound continuation；不展示、不索引、不跨 generation 重放            |
| unknown context compaction    | Context incomplete；不得形成可信 apply proposal/evidence                               |
| cross-tenant cache            | 禁止；cache scope 与 digest 不可证明时 disabled                                        |
| background late callback      | generation fence；只记录 audit，不进入 Context/Proposal                                |
| webhook replay/spoofing       | signature、timestamp、job/invocation identity 验证失败即拒绝                           |
| usage missing                 | 预留上界结算或 reconciliation；不记零、不放宽 budget                                   |
| provider fallback             | 需要新的 qualification/policy/receipt；不静默切换模型、region、state 或 capability     |
| local model drift             | tokenizer/template/quantization/runtime digest drift 使 qualification/evidence expired |
| browser credential exposure   | apply-capable Run 只允许 server/native callback-bound transport                        |

## 11. 拒绝的方案

### 以 Provider 品牌或 model family 作为支持级别

拒绝。同一模型的 text、vision、hosted tool、background 与 realtime 能力的成熟度、数据策略和评测证据不同。

### 只保存 model alias、temperature 和总 token

拒绝。它无法定位 mutable version、reasoning mode、tool policy、state/cache、fine-tune 或非 token usage drift。

### 把 encrypted thinking 当作可审计解释

拒绝。opaque continuation 只用于协议连续性，不提供 truth、approval 或 rationale authority。

### 让 Provider 自动压缩后仍宣称 exact Context

拒绝。submitted Context Pack 与 effective context 必须区分；未知转换使证据降级或阻塞。

### background terminal 直接结束 AgentRun

拒绝。Provider job 只是 subordinate invocation；proposal、approval、commit 与 G3 Closure 仍由 Prodivix authority
决定。
